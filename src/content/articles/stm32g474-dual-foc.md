自平衡机器人对电流环的时序要求很硬：两路电机要在同一个 100μs 周期内完成采样、Clarke/Park 变换、双 PI 计算和 SVPWM 更新。G474 的 HRTIM 和双 ADC 同步模式刚好够用，但够用和好用之间差着几个细节。

## 时序预算

一个 100μs 周期里，实际留给计算的时间不到 60μs：

| 阶段 | 耗时（实测 @170MHz） |
| --- | --- |
| ADC 采样 + 转换（双 ADC 同步） | 约 6μs |
| 电流重构 + Clarke/Park | 约 5μs |
| 双路电流环 PI | 约 8μs |
| 反 Park + SVPWM 占空比计算 | 约 12μs |
| 余量（含中断进出、保护判断） | 约 29μs |

关键是把 Park 变换里的三角函数干掉——用查表 + 线性插值，或者直接复用上一次的电角度增量做旋转，别在中断里调 `sinf()`。

## 双 ADC 同步采样

左右电机的相电流挂在不同的 ADC 上，必须保证同一时刻采样，否则两路电流环的相位基准不一致：

```c
/* ADC1/ADC2 双同步模式，由 TIM5 触发 */
HAL_ADCEx_MultiModeStart_DMA(&hadc1, (uint32_t *)adc_dma_buf, 4);
/* adc_dma_buf: [0]=IA_L [1]=IB_L [2]=IA_R [3]=IB_R */
```

`adc_dma_buf` 的顺序由规则组的 rank 决定，改引脚时最容易在这里出错，且错误表现为"电机抖动但不报错"。

## 速度环降采样

速度环不需要 10kHz，按 10:1 降到 1kHz，用计数器分频触发：

```c
if (++speed_div >= 10) {
    speed_div = 0;
    speed_loop_update();   /* 位置差分 + 速度 PI */
}
```

代价是速度环的等效延迟增加半个速度环周期（0.5ms），在自平衡这种对相位裕度敏感的场景里，需要用更高的速度环增益或前馈来补偿。

> 一个反直觉的结论：电流环从 10kHz 提到 20kHz 带来的收益，远小于把速度环延迟砍掉 0.5ms。
